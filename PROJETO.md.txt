📂 1. Arquitetura e Estrutura de Pastas
O sistema utiliza uma arquitetura de Micro-processamento Assíncrono, onde o NestJS gerencia a API e o fluxo de dados, enquanto o motor Python isolado realiza os cálculos pesados.

Plaintext
src/
├── auth/                         # Módulo de Segurança (JWT / Bcrypt)
│   ├── dto/                      # Validação de Login/Registro (LoginDto)

│   └── auth.service.ts           # Geração de Tokens e Hashing
├── projetos/                     # Gestão de Projetos (Área, Bioma, DMC)

🔐 2. Segurança e Proteção de Dados
JWT (JSON Web Tokens): Todas as rotas sensíveis (como processamento de inventário) exigem um token válido. Implementado com PassportModule e JwtModule.

Validação por DTOs: Uso de class-validator para garantir que as credenciais e dados de projeto cheguem no formato correto.

Sanitização Python: O motor de cálculo trata valores NaN e nulos antes da inserção, prevenindo ataques de SQL Injection e falhas de integridade no banco.

🛢️ 3. Banco de Dados (PostgreSQL / Supabase)
A modelagem foi otimizada para suportar grandes volumes de dados georreferenciados.

perfis: Armazena dados dos usuários e engenheiros (CREA/ART).

projetos: Configurações globais (Fator de Forma, DMC, Área Total).

especies: Catálogo botânico para normalização de nomes comuns.

arvores: Tabela massiva com cálculos individuais (Volume m³, Volume st, Classe Diamétrica).

Update: Adicionada coluna localizacao (TEXT/GEOGRAPHY) para mapeamento GPS.

estatisticas_projeto: Resultados consolidados (Erro de Amostragem, Média por Hectare, T de Student).

🐍 4. Motor de Processamento (Python Engine)
O script foi refatorado para ser resiliente e escalável.

Mapeamento Inteligente (_COLUNAS_MAP): Suporta variações de cabeçalhos como "Nº ÁRVORE", "HT", "DAP" e "CAP" automaticamente.

Resiliência (Fallback de Altura): Se a altura comercial (HC) estiver zerada, o sistema utiliza a altura total (HT) para evitar descarte de dados válidos.

Performance (Bulk Insert): Utiliza executemany do SQLAlchemy para inserir centenas de linhas no PostgreSQL em uma única transação, minimizando o I/O de rede.

Estatística de Campo: Processamento rigoroso de variância, desvio padrão e erro de amostragem (probabilidade de 90%).

🚀 5. Fluxo de Execução
NestJS recebe a planilha via POST /inventario/processar.

Valida o token JWT e salva o arquivo temporariamente.

Invoca o Python Engine de forma assíncrona.

O Python limpa os dados, calcula os volumes e salva no Supabase via Bulk Insert.

O NestJS retorna o JSON com o resumo estatístico para o usuário.
